---
title: "Publish agents to Microsoft 365 and Teams"
description: "Publish a Microsoft Foundry agent to Microsoft Copilot and Microsoft Teams from the Foundry portal."
---

Publish an agent's stable endpoint to Microsoft Copilot and Teams so users can discover and interact with it while you update the active agent version independently.

<Warning>
Microsoft 365 and Teams process and store publishing metadata and agent conversations under their applicable compliance, data residency, and data handling terms. Confirm that these data flows meet your organization's requirements before publishing.
</Warning>

<Note>
Portal publishing isn't supported for projects that disable public network access. For those projects, use the [REST publishing flow](/agents/development/publish-copilot-virtual-network) and enable the source-IP-filtered Activity Protocol route.
</Note>

## Prerequisites

- A Foundry project with an agent version that you tested
- **Foundry User** on the project
- Permission to create Azure Bot Service resources and channels in the target resource group
- The `Microsoft.BotService` resource provider registered in the subscription

The **Azure Bot Service Contributor Role** grants the required Bot Service permissions. Broader **Contributor** or **Owner** roles also work; Foundry roles alone don't grant these permissions.

```bash
az provider register --namespace Microsoft.BotService
```

## Select the active version

The active version receives traffic through the agent's stable endpoint.

1. Open the agent in the Foundry portal.
1. Select **Details**.
1. In **Agent configuration**, edit **Active version**.
1. Select **Always use latest** or choose a specific version.

You can also change the active version from the **Publish** dialog.

## What publishing configures

Foundry:

- Validates the agent name, description, and version.
- Builds a Microsoft Teams app manifest.
- Submits the manifest to the Microsoft Copilot and Teams catalogs.
- Enables the `activity` protocol for channel messages.
- Adds the authorization scheme associated with the selected publish scope.

| Portal scope | API scope | Authorization | Visibility |
| --- | --- | --- | --- |
| **Just you** | `Shared` | `BotServiceRbac` | Appears under **Your agents**; no admin approval required |
| **People in your organization** | `Tenant` | `BotServiceTenant` | Appears under **Built by your org** after admin approval |

## Publish from the Foundry portal

1. In the Foundry portal, open the agent and select **Publish**.
1. Select **Teams and Microsoft Copilot**.
1. Confirm the Azure Bot Service resource. Foundry creates one if needed.
1. Enter the required metadata:

   | Field | Description |
   | --- | --- |
   | **Name** | Display name shown in the agent store |
   | **Publish version** | Three-part version such as `1.0.0` |
   | **Short description** | One sentence describing the agent |
   | **Description** | Longer description of responsibilities and actions |
   | **Developer** | Person or organization that publishes the agent |

1. Under **More**, optionally add HTTPS URLs for the developer website, terms of use, and privacy statement.
1. Select **Next: Publish options**.
1. Choose direct publishing or download the app package for customization.

<Warning>
Don't include secrets, API keys, or sensitive information in publishing metadata. Users can see these fields.
</Warning>

## Publish directly

1. Select **Direct publish**.
1. Choose **Just you** or **People in your organization**.
1. Select **Publish**.

For organization scope, a Microsoft 365 admin must approve the agent in the [Microsoft 365 admin center](https://admin.cloud.microsoft/?#/agents/all/requested).

## Download and customize

1. Select **Download & customize**.
1. Download the `.zip` package.
1. Update the manifest as needed.
1. Upload the custom app in Teams or submit it through your organization's app-management process.

## Verify publishing

1. Open the agent store in Microsoft Copilot or Teams.
1. Find the agent under **Your agents** or **Built by your org**, depending on scope.
1. Send a test message.
1. Confirm the agent responds and its tools work.

## Limitations

- Microsoft 365 doesn't support file uploads or image generation for published agents; Teams does.
- Microsoft 365 and Teams channel traffic doesn't use Private Link.
- Published agents don't support streaming responses or citations.

## Troubleshooting

| Symptom | Resolution |
| --- | --- |
| Publishing fails with HTTP 403 | For a private-network project, use the [REST publishing flow](/agents/development/publish-copilot-virtual-network). |
| Bot Service creation fails | Verify resource-group permissions and register `Microsoft.BotService`. |
| Organization users can't find the agent | Confirm Microsoft 365 admin approval and tenant app policies. |
| The agent doesn't respond | Verify the Bot Service resource, active agent version, and authorization scheme. |
