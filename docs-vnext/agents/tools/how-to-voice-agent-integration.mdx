Use Voice Live with [Microsoft Foundry Agent Service](https://learn.microsoft.com/azure/ai-foundry/agents/overview) to build real-time voice applications in Python, C#, Java, or JavaScript. This guide builds on [Quickstart: Create a voice agent with Foundry Agent Service and Voice Live](/agents/tools/voice-live-agents-quickstart) and covers version pinning, cross-resource connections, proactive messages, interim responses, conversation continuity, and diagnostics.

Agent integration centralizes configuration and conversational logic in the agent. Applications connect by agent ID and can switch agent versions without changing the client workflow. To build without Foundry Agent Service, see the [Voice Live API quickstart](https://learn.microsoft.com/azure/ai-services/speech-service/voice-live-quickstart).

<Tip>
You don't need to deploy an audio model in Microsoft Foundry. Voice Live is fully managed and deploys the audio model automatically. For model availability, see the [Voice Live overview](https://learn.microsoft.com/azure/ai-services/speech-service/voice-live).
</Tip>

## Prerequisites

This guide uses the latest Microsoft Foundry portal and Foundry Agent Service version. You need:

- An Azure subscription. [Create one for free](https://azure.microsoft.com/pricing/purchase-options/azure-account?cid=msft_learn).
- A [Microsoft Foundry resource](/setup/multi-service-resource) in a region supported by Voice Live.
- A deployed model. If needed, complete [Quickstart: Set up Microsoft Foundry resources](/get-started/quickstart-create-foundry-resources).
- The `Azure AI User` role, assigned through **Access control (IAM)** > **Add role assignment**.
- The development tools for your selected language, as listed in the following table. See [Prepare your development environment](/developer-experience/install-cli-sdk) for the common tools.

| Language | Requirements |
|---|---|
| Python | [Python 3.10 or later](https://www.python.org/). See the [VS Code Python tutorial](https://code.visualstudio.com/docs/python/python-tutorial#_install-a-python-interpreter) for installation guidance. |
| C# | [.NET 8.0 SDK or later](https://dotnet.microsoft.com/download/dotnet/8.0). |
| Java | [JDK 11 or later](https://learn.microsoft.com/java/azure/jdk/) and [Apache Maven](https://maven.apache.org/download.cgi). |
| JavaScript | [Node.js 18 or later](https://nodejs.org/) and [SoX](https://sox.sourceforge.io/) for microphone capture with `node-record-lpcm16`. |

<Note>
The JavaScript SDK is designed for browser applications with built-in WebSocket and Web Audio support. The quickstart uses Node.js with `node-record-lpcm16` and `speaker` for a console application. For a browser-based interface, see the [Voice Live universal assistant sample](https://github.com/microsoft-foundry/voicelive-samples/tree/main/voice-live-universal-assistant).
</Note>

## Prepare the environment and create the agent

Complete [Quickstart: Create a voice agent with Foundry Agent Service and Voice Live](/agents/tools/voice-live-agents-quickstart) to configure the environment and agent, then test the first conversation.

## Configure agent integration

Use Microsoft Entra ID credentials for agent mode. Agent invocation in this flow doesn't support key-based authentication. For local development and deployment, use `AzureCliCredential`, `DefaultAzureCredential`, or another Entra token credential supported by your SDK.

Identify the target project and agent in the session configuration. Include the agent and project names, then optionally add an agent version or conversation ID.

| Language | Session configuration | Required fields | Start the session |
|---|---|---|---|
| Python | `agent_config` | `agent_name`, `project_name` | `connect(..., agent_config=self.agent_config)` |
| C# | `AgentSessionConfig` | `AgentName`, `ProjectName` | `StartSessionAsync(SessionTarget.FromAgent(agentConfig))` |
| Java | `AgentSessionConfig` | `agentName`, `projectName` | `client.startSession(agentConfig)` |
| JavaScript | `AgentSessionConfig` in the `agent` property | `agentName`, `projectName` | `client.createSession({ agent: this.agentConfig })` |

Pin the SDK or API version used by the quickstart and this guide to avoid schema drift during preview:

| Language | Version |
|---|---|
| Python | Pin a supported `api_version` consistently across samples. |
| C# | `Azure.AI.VoiceLive` 1.1.0-beta.3 |
| Java | `azure-ai-voicelive` 1.0.0-beta.5 |
| JavaScript | `@azure/ai-voicelive` 1.0.0-beta.3 |

## Connect to a specific agent version

Pinning an agent version lets production use a stable version while development tests a newer version. Set `AGENT_VERSION` or pass the equivalent constructor or configuration value. If you omit the version, Voice Live connects to the latest agent version.

| Language | Read the value | Apply the value |
|---|---|---|
| Python | Read `AGENT_VERSION` in `main()`. | Pass `agent_version` to `BasicVoiceAssistant`, then add it to `self.agent_config`. |
| C# | Read `AGENT_VERSION` in `Main()`. | Pass `agentVersion` to `BasicVoiceAssistant`, then set `config.AgentVersion`. |
| Java | Read `AGENT_VERSION` in `main()`. | Pass `agentVersion` to `BasicVoiceAssistant`, then call `config.setAgentVersion(agentVersion)`. |
| JavaScript | Read `AGENT_VERSION` from `process.env`. | Pass `agentVersion` to `BasicVoiceAssistant`, then include it in `agentConfig`. |

The value must match a version returned when you create or update the agent with the Foundry Agent SDK.

## Connect across Foundry resources

Voice Live can process audio in one Foundry resource while connecting to an agent in another. Use this arrangement to separate environments, use regional feature availability, or divide workloads across resources.

Set these environment variables:

| Variable | Value |
|---|---|
| `FOUNDRY_RESOURCE_OVERRIDE` | Name of the Foundry resource that hosts the agent project, such as `YOUR_AGENT_RESOURCE`. |
| `AGENT_AUTHENTICATION_IDENTITY_CLIENT_ID` | Managed identity client ID of the Voice Live resource. |

Read both values when the application starts, pass them to the assistant, and add them to the language-specific agent configuration:

| Language | Configuration fields |
|---|---|
| Python | Add both values to `self.agent_config`. |
| C# | Set `config.FoundryResourceOverride` and `config.AuthenticationIdentityClientId`. |
| Java | Call `config.setFoundryResourceOverride(...)` and `config.setAuthenticationIdentityClientId(...)`. |
| JavaScript | Conditionally add both values to `agentConfig`. |

<Info>
Assign the Voice Live resource's managed identity the `Azure AI User` role on the target agent resource.
</Info>

## Send a proactive message

To start the conversation as soon as the session is ready:

1. Initialize a Boolean greeting flag to `false`.
2. In the session-updated handler, check the flag so the greeting runs once.
3. Add the greeting instruction to the conversation and request a response.

| Language | Session-ready handler | Create the greeting | Generate audio |
|---|---|---|---|
| Python | `SESSION_UPDATED` | `conn.conversation.item.create(...)` | `conn.response.create()` |
| C# | `SessionUpdateSessionUpdated` | `SendCommandAsync(...)` with `conversation.item.create` | Send `response.create`. |
| Java | `SESSION_UPDATED` | `sendEvent(new ClientEventConversationItemCreate()...)` | `sendEvent(new ClientEventResponseCreate())` |
| JavaScript | `onSessionUpdated` | `session.addConversationItem(...)` | `session.sendEvent({ type: "response.create" })` |

## Add interim responses

Interim responses bridge delays during tool calls or high-latency agent responses. Use an LLM-generated response for dynamic wording or a pre-generated response for deterministic messaging.

| Mode | Use case |
|---|---|
| `LlmInterimResponseConfig` | Dynamic, context-aware responses. |
| `InterimResponseTrigger` | Pre-generated or branded responses. |

Configure the interim response when setting up the session:

| Language | Configuration path |
|---|---|
| Python | Attach `LlmInterimResponseConfig` to `RequestSession.interim_response`, then call `conn.session.update(...)`. |
| C# | Serialize `LlmInterimResponseConfig` into `VoiceLiveSessionOptions.InterimResponse`, then call `ConfigureSessionAsync(...)`. |
| Java | Add `LlmInterimResponseConfig` to `VoiceLiveSessionOptions.interimResponse`, then send `ClientEventSessionUpdate`. |
| JavaScript | Set `interimResponse`, then call `session.updateSession(...)`. |

## Handle interrupted responses

When a user interrupts agent audio, the stored text can include content the user didn't hear. Enable truncation-aware handling so follow-up responses, thread history, and trace records reflect delivered audio more closely.

The quickstart samples cancel the current response when speech starts:

| Language | Cancellation mechanism |
|---|---|
| Python | `response.cancel()` |
| C# | `CancelResponseAsync()` |
| Java | `ClientEventResponseCancel` |
| JavaScript | `response.cancel` event |

These samples don't configure `auto_truncate` in `turn_detection`. For configuration details, see [Handle voice interruptions in chat history](https://learn.microsoft.com/azure/ai-services/speech-service/how-to-voice-live-auto-truncation).

<Note>
Foundry Agent Service thread messages and traces are based on text content. Without automatic truncation, they can differ from the audio played before an interruption.
</Note>

## Reconnect to a conversation

Set `CONVERSATION_ID` to continue a previous agent conversation. When the session becomes ready, capture the session ID from the session metadata and write it to a timestamped file under `logs/`.

| Language | Read the session ID | Apply the conversation ID |
|---|---|---|
| Python | Read session metadata from `SESSION_UPDATED`. | Add `conversation_id` to `self.agent_config`. |
| C# | Read `sessionUpdated.Session?.Id`. | Set `config.ConversationId`. |
| Java | Extract `id` from the `SESSION_UPDATED` event. | Call `config.setConversationId(conversationId)`. |
| JavaScript | Read `context.sessionId` in `onSessionUpdated`. | Add `conversationId` to `agentConfig`. |

Use the conversation ID to resume context and the session ID to correlate logs and diagnostics. A conversation ID is scoped to its agent and project; using it with another agent starts a new conversation.

## Log session metadata

Create one timestamped log per run and append entries throughout the conversation lifecycle. At minimum, record the session ID, agent name, and voice configuration when the session becomes ready. This information supports troubleshooting, run correlation, and later reconnection with `CONVERSATION_ID`.

Treat agent thread and trace records as text-turn history rather than exact playback history. If the application supports interruptions, combine session logging with automatic truncation.

## Migrate from Agent Service (classic)

If the application uses Agent Service (classic), see [Migrate from Agent Service (classic) to Foundry Agent Service](https://learn.microsoft.com/azure/ai-foundry/agents/how-to/migrate).

### Voice Live SDK changes

| Classic (v1) | New (v2) |
|---|---|
| `agent-id` query parameter | `agent_name` in `AgentConfig` or `AgentSessionConfig` |
| `agent-project-name` query parameter | Project endpoint in the client constructor |
| `agent-access-token` query parameter | Handled automatically by the SDK |
| Manual `connect()` with a query dictionary | Typed `AgentSessionConfig` passed to session options |

### Minimum SDK versions

| Language | Package | Minimum version |
|---|---|---|
| Python | `azure-ai-voicelive` | 1.0.0b5 |
| C# | `Azure.AI.VoiceLive` | 1.1.0-beta.2 |
| Java | `azure-ai-voicelive` | 1.0.0-beta.5 |
| JavaScript | `@azure/ai-voicelive` | 1.0.0-beta.3 |

### Before and after: Python connection setup

The classic integration passes raw query parameters to `connect()`:

```python
async with connect(
    endpoint=self.endpoint,
    credential=self.credential,
    query={
        "agent-id": self.agent_id,
        "agent-project-name": self.foundry_project_name,
        "agent-access-token": agent_access_token,
    },
) as connection:
```

The current integration uses a typed `AgentSessionConfig`:

```python
from azure.ai.voicelive import AgentConfig, AgentSessionConfig

agent_config = AgentConfig(agent_name=agent_name)
agent_session_config = AgentSessionConfig(agent_config=agent_config)

session_options = VoiceLiveSessionOptions(
    agent_session_config=agent_session_config,
    # Add other session options here.
)
```
