---
title: "Use GPT-Live via WebRTC"
description: "Connect to GPT-Live via WebRTC for low-latency, browser-native audio streaming."
---

WebRTC carries low-latency audio on a negotiated media track and session events on a data channel. For server-to-server
integrations, see [Use GPT-Live over WebSocket](/models/capabilities/gpt-live).

## Prerequisites

- A Microsoft Foundry resource with a `gpt-live-1` deployment.
- A trusted backend that holds the API key or Microsoft Entra ID credentials.

GPT-Live doesn't support ephemeral client keys. The browser sends its SDP offer through the trusted backend, while
audio connects directly between the browser and the service.

## Create the browser offer

```javascript
const pc = new RTCPeerConnection();
pc.addTransceiver("audio", { direction: "sendrecv" });
const dataChannel = pc.createDataChannel("oai-events");

const offer = await pc.createOffer();
await pc.setLocalDescription(offer);

const answer = await fetch("/live/session", {
  method: "POST",
  headers: { "Content-Type": "application/sdp" },
  body: offer.sdp,
}).then((response) => response.text());

await pc.setRemoteDescription({ type: "answer", sdp: answer });

dataChannel.addEventListener("message", ({ data }) => {
  const event = JSON.parse(data);
  console.log(event.type, event);
});
```

## Create the session on the backend

The backend forwards the browser's offer and session configuration to the service, then returns the SDP answer. Keep
credentials on the backend.

```javascript
const resourceName = process.env.FOUNDRY_RESOURCE_NAME;
const apiKey = process.env.FOUNDRY_API_KEY;

const response = await fetch(
  `https://${resourceName}.openai.azure.com/openai/v1/live/sessions`,
  {
    method: "POST",
    headers: {
      "api-key": apiKey,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      session: {
        model: "gpt-live-1",
        instructions: "Be concise.",
        delegation: { type: "client" },
      },
      transport: { type: "webrtc", sdp: offerSdp },
    }),
  },
);

const { session, transport } = await response.json();
// Save session.id for sideband control and return transport.sdp to the browser.
```

Save `session.id` if the backend attaches a
[sideband WebSocket](/models/capabilities/gpt-live#attach-a-sideband-websocket).

## WebRTC transport differences

- Audio uses the negotiated media track. Don't send `session.input_audio.append` or expect
  `session.output_audio.delta` on the data channel.
- RTP synchronizes media, so audio doesn't carry JSON timing fields.
- Session updates, context events, delegation events, transcripts, usage, and errors use the same schema as WebSocket.
