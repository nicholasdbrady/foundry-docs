WebRTC supports browser-based and native client applications that need low-latency, real-time audio streaming with GPT-Live. Audio travels on a negotiated media track, while session events travel over a data channel.

For server-to-server integrations, see [Use GPT-Live over WebSocket](/models/capabilities/gpt-live).

## Prerequisites

- An [Azure subscription](https://azure.microsoft.com/pricing/purchase-options/azure-account?cid=msft_learn)
- A [Microsoft Foundry resource](https://learn.microsoft.com/azure/ai-services/multi-service-resource)
- A deployment of the `gpt-live-1` model
- A trusted backend that holds your API key or Microsoft Entra ID credentials

<Warning>
GPT-Live doesn't support ephemeral client keys. Never expose service credentials to the browser; authenticate session creation from a trusted backend.
</Warning>

## Establish the connection

1. In the browser, create an `RTCPeerConnection`, add an audio transceiver and a data channel, and create an SDP offer.
1. Send the SDP offer to your backend.
1. Have the backend forward the offer to the service in an authenticated session-creation request.
1. Relay the returned SDP answer to the browser.
1. Apply the answer in the browser.

After negotiation, audio flows directly between the browser and the service over the media track. The data channel carries JSON events.

### Create the browser offer

```javascript
const pc = new RTCPeerConnection();
pc.addTransceiver("audio", { direction: "sendrecv" });
const dataChannel = pc.createDataChannel("oai-events");

const offer = await pc.createOffer();
await pc.setLocalDescription(offer);

const answer = await fetch("/live/session", {
  method: "POST",
  headers: { "Content-Type": "application/sdp" },
  body: offer.sdp,
}).then((response) => response.text());

await pc.setRemoteDescription({ type: "answer", sdp: answer });

dataChannel.addEventListener("message", ({ data }) => {
  const event = JSON.parse(data);
  console.log(event.type, event);
});
```

### Create the session from the backend

The backend sends the browser's SDP offer and the session configuration to the service, then returns the SDP answer to the browser.

```javascript
const resourceName = process.env.FOUNDRY_RESOURCE_NAME;
const apiKey = process.env.AZURE_OPENAI_API_KEY;

const response = await fetch(
  `https://${resourceName}.openai.azure.com/openai/v1/live/sessions`,
  {
    method: "POST",
    headers: {
      "api-key": apiKey,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      session: {
        model: "gpt-live-1",
        instructions: "Be concise.",
        delegation: { type: "client" },
      },
      transport: { type: "webrtc", sdp: offerSdp },
    }),
  },
);

const { session, transport } = await response.json();
// Save session.id for sideband control and return transport.sdp to the browser.
```

Save `session.id` if the backend needs to attach a [sideband WebSocket](/models/capabilities/gpt-live#observe-a-session-with-a-sideband-websocket).

## Compare WebRTC and WebSocket

- Don't send `session.input_audio.append` on the WebRTC data channel or expect `session.output_audio.delta` there. Audio flows over the media track.
- RTP synchronizes input and output media; JSON timing fields aren't included.
- Other session events use the same schema as WebSocket, including context, delegation, transcript, usage, and error events.
