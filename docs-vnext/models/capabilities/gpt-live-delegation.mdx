---
title: "Delegate work in GPT-Live"
description: "Configure GPT-Live delegation and complete client-actionable function calls."
---

GPT-Live can delegate search, deeper reasoning, or external actions while the live interaction continues. Configure
delegation when starting a [GPT-Live session](/models/capabilities/gpt-live#configure-the-session).

| Mode | Description |
| --- | --- |
| Client delegation | The application performs the work and returns context. This provides the most control. |
| Responses delegation | GPT-Live routes work to a configured Responses API deployment. Hosted tools run server-side; function calls that require a client return to the application. |

Omitted or `null` delegation selects client delegation.

## Choose a mode

Use Responses delegation when its managed model-and-tool loop fits the task. Use client delegation when the application
must validate or redact results, select custom backends, control context, or enforce custom routing and budgets.

In both modes, the application must enforce permissions and required confirmations before running tools.

## Configure delegation

Client delegation:

```json
{
  "delegation": { "type": "client" }
}
```

Responses delegation:

```json
{
  "delegation": {
    "type": "responses",
    "responses": {
      "model": "gpt-5.5",
      "instructions": "Use tools when current information is required.",
      "tools": [
        { "type": "web_search" },
        {
          "type": "function",
          "name": "get_weather",
          "description": "Get current weather for a location.",
          "parameters": {
            "type": "object",
            "properties": { "location": { "type": "string" } },
            "required": ["location"],
            "additionalProperties": false
          }
        }
      ],
      "tool_choice": "auto",
      "parallel_tool_calls": true
    }
  }
}
```

`delegation.responses.service_tier` accepts `auto`, `default`, `flex`, or `priority`. A later `session.update` replaces
the complete delegation object; it doesn't patch nested fields. Set `delegation` to `null` to return to client
delegation.

## Handle client delegation

`session.delegation.created` identifies work for the client. The object contains correlation metadata rather than task
text, so use transcript events and application state to determine the requested action.

```json
{
  "type": "session.delegation.created",
  "event_id": "event_delegation",
  "offset_ms": 1000,
  "delegation": {
    "id": "item_delegation_123",
    "type": "delegation",
    "target": "client"
  }
}
```

Return user-facing content with `session.commentary.append`, or quiet context with `session.thinking.append`. Set
`delegation_id` to the ID from the created event.

```json
{
  "type": "session.commentary.append",
  "event_id": "event_result_1",
  "delegation_id": "item_delegation_123",
  "content": "It is 62 degrees and raining in Seattle."
}
```

An acknowledgment confirms context injection, not that the model consumed or spoke the result.

## Handle Responses delegation

For Responses delegation, `session.delegation.created` includes `target: "responses"` and a `response_id`. Subsequent
Responses events arrive inside a `response.event` envelope. Dispatch on the nested `event.type` and preserve the outer
`delegation_id`.

```json
{
  "type": "response.event",
  "event_id": "event_response_1",
  "delegation_id": "item_delegation_456",
  "event": {
    "type": "response.output_text.delta",
    "item_id": "msg_123",
    "delta": "The forecast is"
  }
}
```

Delegated output is injected into the live session, but backend completion doesn't guarantee that the user heard it.

### Complete a client-actionable function call

Read completed calls from the nested `response.output_item.done` event:

```json
{
  "type": "response.event",
  "delegation_id": "item_delegation_456",
  "event": {
    "type": "response.output_item.done",
    "item": {
      "type": "function_call",
      "call_id": "call_123",
      "name": "get_weather",
      "arguments": "{\"location\":\"Seattle\"}"
    }
  }
}
```

Run the authorized handler, then submit the result:

```json
{
  "type": "response.item.create",
  "event_id": "event_function_output_1",
  "item": {
    "type": "function_call_output",
    "call_id": "call_123",
    "output": "{\"temperature\":62,\"conditions\":\"rain\"}"
  }
}
```

Submit one result for every pending call, then continue the response explicitly:

```json
{
  "type": "response.create",
  "event_id": "event_continue_1"
}
```

Appending a function result doesn't continue the response automatically. Read `response.event` envelopes until a
terminal event such as `response.completed` or an error.
